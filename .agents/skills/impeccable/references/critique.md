# Product design critique (adapted)

Derived from Impeccable skill/reference/critique.md at
bbcb29d9dee6c94915d760bcfc36818ad5be66ad; see [../NOTICE.md](../NOTICE.md).
Modified for Map Capital Cities: terminology, tasks and user perspectives.

Resolve one stable target. Read relevant source and product context, then inspect
the rendered flow when a browser is available. Assess design specificity before
technical findings so the checklist does not anchor visual judgment. This manual
review has no detector, overlay, stored snapshot or delegated assessment
requirement. Describe the actual method and evidence used.

Evaluate whether composition and interaction are grounded in this product or
could be exchanged with an unrelated product unchanged. Review hierarchy,
information architecture, discoverability, emotional fit, typography, color,
states, copy and edge cases against the incumbent visual language. A popular
font or a card alone is not a defect.

Inspect cognitive load: can users identify the primary task; are decisions
grouped; is memory demanded across screens; do competing elements hide priority;
is complexity disclosed when needed? Option-count and working-memory heuristics
are prompts to inspect comprehension, not hard limits requiring hidden scores.

Use these usability lenses when relevant:

1. System status: actions, progress and current location stay legible.
2. Real-world match: terminology and order suit browsing and editing capitals.
3. Control/freedom: cancel, back and recovery paths remain clear.
4. Consistency: similar actions share appearance and behavior.
5. Error prevention: defaults and constraints reduce likely mistakes.
6. Recognition: context is visible without memorizing earlier screens.
7. Efficiency: repeat users act quickly without complicating the basics.
8. Minimalism: each emphasis supports the current task.
9. Error recovery: specific messages preserve work and show a next step.
10. Help: task-focused guidance is available where needed.

Walk relevant paths such as finding a capital, changing a marker color or
submitting a CRUD dialog as a first-time, keyboard/screen-reader or interrupted
mobile user. Ground the tasks in README and the assignment, without inventing
audience facts.

Report the overall impression, strengths, highest-impact problems and practical
recommendations with locations and user consequences. Use P0–P3 severity as in
[audit.md](audit.md). Separate visual judgment from measured defects and say which
states were not inspected. Optional scores cover only inspected criteria with a
disclosed denominator; never imply a detector or compliance pass.
